# Практика №4 · Вариант 3 · Сетевая НСУ: QUdpSocket и MAVLink

Отдельный проект `Practical_04_MavlinkGroundStation`, C++17, Qt Widgets + Qt Network.
Выполнены варианты 3 заданий 1–4 и интеграционное задание из
«Практика 4 ПО ОНИ.pdf».

## Сборка и запуск

Откройте `CMakeLists.txt` в Qt Creator и выберите комплект Qt 6 или Qt 5.15.
Нужны модули Core, Network, Widgets, Charts, 3DCore, 3DRender, 3DExtras, 3DInput,
Multimedia и Test (для проверок).

Из каталога `Practise_4`:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j4
./build/Practical_04_MavlinkGroundStation
ctest --test-dir build --output-on-failure
```

Модель и сетевой слой собираются отдельно, без графических модулей:

```sh
cmake -S . -B build/model -DGROUNDSTATION_BUILD_GUI=OFF
cmake --build build/model
ctest --test-dir build/model --output-on-failure
```

## Два приложения

- `Practical_04_MavlinkGroundStation` — НСУ. Слушает UDP-порт 14540, показывает
  канал, телеметрию, график, таблицу, 3D-полёт, команды и журналы. Внизу левой
  панели — встроенный эмулятор БПЛА (как `m_uavSimulator` в PDF), чтобы весь
  эталонный сценарий выполнялся в одном окне.
- `Practical_04_UavEmulator` — отдельный процесс с тем же `UavSimulator`.
  По умолчанию шлёт на `127.0.0.1:14540` с порта 14552 (встроенный — с 14551).
  `--start` начинает передачу сразу после запуска. Одновременно запускайте один
  эмулятор: учёт `seq` в НСУ, как в PDF, ведётся по одному потоку.

## Эталонный сценарий

1. Запуск НСУ — «Связь отсутствует», порт закрыт, кнопки команд заблокированы.
2. «Открыть канал» — НСУ слушает UDP 14540, «Ошибок нет».
3. «Запустить эмулятор» (или отдельное приложение) — пакеты поступают, видны
   адрес/порт отправителя, счётчики, координаты, высота и режим; график растёт.
4. Высота взлёта, например 80 м → «Взлёт» → диалог подтверждения → `COMMAND_LONG`
   с `MAV_CMD_NAV_TAKEOFF` (22, высота в param7, param4–6 = NaN).
5. Эмулятор отвечает `COMMAND_ACK`; статус и «Журнал команд» показывают результат.
   Аппарат набирает высоту 5 м/с в `GUIDED` и облетает дом по кругу 60 м.
6. «Отключить БПЛА» — через 3 с «Связь потеряна», команды заблокированы.
7. «Запустить эмулятор» снова — «Связь восстановлена», команды доступны.

Имитация отказов: «Повредить пакет» (байт 3 ^ 0xFF, как в PDF), «Пропустить 2 пакета»
(номера `seq` расходуются, НСУ считает 2 потерянных), «Отказ сенсора» (HEARTBEAT
с `MAV_STATE_CRITICAL`, взлёт отклоняется `MAV_RESULT_DENIED`), флажок «Отвечать на
команды» (без него эмулятор молчит и через 3 с НСУ пишет «Подтверждение не получено»).
«Стоп» — `MAV_CMD_NAV_LOITER_UNLIM` (зависание, режим `POS_HOLD`), «Посадка» —
`MAV_CMD_NAV_LAND` (режим `AUTO` до земли).

## Варианты 3

| Задание | Реализация |
| --- | --- |
| 1 · журнал сетевых событий | `listEventLog`: `[время] ТИП · событие`. Только значимое: первое подключение, HEARTBEAT `sysid/compid`, потери, ошибки, смена режима, команды, ответы, потеря/восстановление связи. Не пишется каждый пакет |
| 2 · таблица телеметрии | `tableTelemetry`: время, System ID, Component ID, широта, долгота, высота, режим; не чаще строки в секунду, не более 200 строк |
| 3 · подтверждение оператором | `QMessageBox::question` перед взлётом; «Нет» — команда не уходит, запись в журнале |
| 4 · безопасный режим | При потере связи «Взлёт», «Посадка», «Стоп» блокируются, статус красный, событие в журнале; при восстановлении — разблокировка и «Связь восстановлена» в строке состояния |

Обязательная часть всех заданий также выполнена: метки канала и телеметрии,
`QChartView chartView` (300 точек), `spinTakeoffAltitude` 10–500 м шаг 10, начальное 50,
`btnTakeoff`, `btnLand`, `labelCommandStatus`, `listCommandLog`, таймер контроля связи 1 с,
проверка длины/CRC, повреждение пакета, отключение БПЛА, блокировка команд.
Ожидание `COMMAND_ACK` 3 с (вариант 1 задания 3) добавлено, так как его требует
тестовый сценарий 8 интеграционного задания.

## MAVLink

Сгенерированной библиотеки MAVLink в системе нет, поэтому выбран учебный путь PDF,
но без упрощения формата: `MavlinkMessageParser` реализует настоящий кадр MAVLink 2
(0xFD, len, флаги, seq, sysid, compid, 3-байтовый msgid, усечение нулей в конце
полезной нагрузки), CRC-16/MCRF4XX и `CRC_EXTRA` из `common.xml` (HEARTBEAT 50,
GLOBAL_POSITION_INT 104, COMMAND_LONG 152, COMMAND_ACK 143). Принимаются и кадры
MAVLink 1 (0xFE). Значения `CRC_EXTRA` пересчитаны по определениям полей, а пакеты
эмулятора проверены независимым декодером на Python. Поле `custom_mode` использует
учебную нумерацию режимов PDF (0 MANUAL … 5 AUTO); в PX4/ArduPilot она другая.
Высота в НСУ — `relative_alt` (над точкой старта), координаты — `lat/lon / 1e7`.

## Архитектура

- `TelemetryModel` — последнее состояние БПЛА; `linkStateChanged` только при изменении.
- `MavlinkManager` — `QUdpSocket`, цикл `while (hasPendingDatagrams())`, адрес/порт
  отправителя из `QNetworkDatagram`, потери по `seq`, тайм-аут связи 3 с, команды,
  ожидание `COMMAND_ACK` 3 с, без повторной отправки до ответа.
- `MavlinkMessageParser` — проверка и разбор/сборка пакетов, без сокетов.
- `UavSimulator` — эмулятор: телеметрия 10 Гц, HEARTBEAT 1 Гц, ответы на команды.
- `MainWindow` (`mainwindow.ui`) — только представление.

В модели и сетевом слое нет `ui->`; в окне нет разбора MAVLink, CRC и сборки датаграмм.
Все поля закрыты, события идут сигналами, `connect` — только указательный синтаксис.
Поэтому слоты названы `onTakeoffClicked()`, а не `on_btnTakeoff_clicked()`:
автосоединение `connectSlotsByName` вызвало бы слот второй раз.
Серия графика и маркер 3D-сцены создаются один раз и только обновляются.

Отличия от фрагментов PDF, сделанные сознательно:

- ошибка пишется в `labelErrorStatus` («Последняя ошибка»), а не в `labelLinkStatus`:
  иначе один повреждённый пакет перезаписывал бы «Связь установлена»;
- «Принято» — корректные пакеты, «Ошибочных» — отклонённые по длине/CRC;
  повреждённый пакет израсходовал `seq`, поэтому он учитывается и как потерянный;
- ось времени графика — реальное время приёма, а не `static double += 0.1`;
- таймер контроля связи срабатывает раз в секунду, поэтому потеря фиксируется
  через 3–4 с после последнего пакета;
- `UavSimulator::start()` возвращает `bool`; повторный старт продолжает тот же полёт
  (имитация пропадания канала, а не перезагрузки БПЛА);
- сокеты открываются с `DontShareAddress`: вторая НСУ на том же порту получит ошибку.

Как в `practise_3`, из прошлых работ перенесены `Scene3D`, `DroneVisual`, `FlightAudio`,
`Point3D` и ресурсы `drone.jpg`, `drone_sound.mp3`, `critical.mp3`: вкладка «3D-полёт»
показывает аппарат относительно точки старта, звук предупреждает о потере связи и аварии.

## Проверки и отчёт

`groundstation_tests` проверяет парсер, модель, сетевой слой и эмулятор через
настоящий UDP на loopback; `groundstation_window_tests` проходит все 10 обязательных
сценариев PDF кнопками окна. Повторное получение скриншотов:

```sh
QT_QPA_PLATFORM=offscreen GROUNDSTATION_SCREENSHOTS="$PWD/report/screenshots" \
  ./build/groundstation_window_tests
```

Результаты, скриншоты и ответы на контрольные вопросы — в [отчёте](report/REPORT.md).
